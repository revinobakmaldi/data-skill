# Request types

Use these labels consistently:

- `new-report-delivery`: new dashboard, new semantic model, new KPI pack, redesign from scratch
- `existing-report-ops`: refresh issue, broken visual, wrong numbers, permissions, performance, support request
- `semantic-model-change`: measure logic, relationship changes, naming cleanup, model audit, structural remediation
- `report-change`: layout, navigation, themes, PBIR edits, custom visuals, slicers, bookmarks

Questions that must be answered early:

- Who is the audience?
- What decision should this artifact improve?
- What grain should the primary fact table represent?
- What KPI definitions are already approved vs still disputed?
- Is this a file-based PBIP workflow or a live Desktop/Fabric workflow?
