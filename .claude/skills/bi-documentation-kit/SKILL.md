# BI documentation kit

Use this skill to standardize what gets written down after BI work.

## Workflow

1. Pick the right artifact:
   - metric note
   - semantic-model note
   - incident summary
   - stakeholder explanation
2. Use `templates/documentation-template.md`.
3. Preserve rationale, caveats, and validation context.
4. Keep technical and stakeholder explanations clearly separated.

## Rules

- Do not casually rewrite business definitions.
- Record what changed, why it changed, and what assumptions still remain.
- Prefer concise durable notes over long storytelling.
