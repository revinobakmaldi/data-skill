# Model review checklist

- Grain is explicit for every fact-like table
- Relationships are directional and non-ambiguous
- Many-to-many usage is justified and explained
- Calendar/date strategy is explicit
- Measures vs calculated columns are chosen deliberately
- Naming conventions are consistent
- RLS impact is considered where relevant
- Logic placement is justified across source, model, and report layers
- Performance risks are named, not implied
- Validation path back to source truth exists
